Thanks — concrete structures are exactly what's useful here, and yours surfaced something I should raise myself rather than let you discover.

**What already works with your layout.** The flat shape (`folder/author/title[...].epub`) is handled: when nothing better is available, the book's parent folder becomes the author, so your `author` directory is read as the author rather than ignored. Bracketed and parenthesised spans are dropped from author names, and underscores between letters are read as the full stops a filesystem won't take (`Herbert G_ Wells` → `Herbert G. Wells`).

**Where your layout breaks it.** Your series shape, `folder/author/serial/#number_title.epub`, would show the *series* as the author, because the rule takes the immediate parent folder and that's the series directory. That's a real gap, and it's the same theme @Uri-Tauber raised about series in filenames. Walking up a level when the immediate parent looks like a series is the obvious direction; it isn't implemented.

**On `author - title` from OPDS.** Filename parsing only splits on ` -- ` (a double dash surrounded by spaces), never on a single dash. That's deliberate rather than an omission: single dashes live inside titles and names constantly — *Spider-Man*, *Jean-Paul*, *Anne-Marie* — so splitting on them would corrupt far more names than it would recover. With the double dash the separator is unambiguous.

**The part that matters most, and it's a limitation not a feature.** If your library is not in the Latin alphabet, most of this is moot in a way I should state plainly: the text normalisation used for sorting and search drops any script it doesn't map. I checked rather than assumed — `Война и мир` normalises to an empty string, as do Greek and CJK titles, while `L'Énéide` correctly becomes `eneide`. The practical effect is that non-Latin titles are not searchable, sort together under an empty key, and can't be reached from the A-Z grid. Enabling "Use book metadata" gets you the correct title and author *displayed* from inside the EPUB, but it does not fix search or sorting, because those run on the normalised form.

That's fixable — keeping unmapped scripts in the normalised string instead of discarding them would restore search and sorting within a script — but it isn't done today, and I'd rather say so up front. If your library is largely non-Latin, I'd genuinely like to know: it changes how much this feature is worth to you as it stands.
