# Library v1.1 — "The shelf becomes yours"

Status: designed, not started. 2026-08-06.
Prerequisite: the upstream series (#2885-#2889, tracking #2878) merges first — v1.1 is
prototyped on this fork, then proposed upstream as follow-up PRs. Nothing here may land
in the series while it is under review.

## Problem

Three pressures on the current shelf, one root cause each:

1. The sort strip holds five text tabs; French already overflows the right edge
   ("Rechercher" was clipped in the 800 px strip). Title Z-A pays a full tab for a
   rare use.
2. There is no per-book action surface: Confirm opens, and nothing else exists. The
   author-provenance honesty stored in every record (folder / cache / OPF) has no
   screen to appear on.
3. Nothing on the shelf belongs to the reader. Sorts and search are *queries*;
   there is no way to say "this one matters to me". #2427 asked for collections;
   a favorites flag is its minimal, shippable form.

## The organizing principle: long-press = secondary action of the focused thing

The current map allocates long-press Confirm globally to the sort menu. v1.1
re-allocates it contextually, which resolves every gesture conflict at once:

| Context focused      | Confirm (short)                   | Confirm (long)                  |
|----------------------|-----------------------------------|---------------------------------|
| A book row           | Open the book                     | **Book menu** (new)             |
| The sort strip       | Activate tab / open A-Z grid      | **Flip direction** (new)        |
| The A-Z grid         | Jump to letter                    | —                               |

The standalone sort menu is **removed**. Its two jobs are covered better: the strip
itself is the visible list of orders, and direction gains three affordances (below).
Risk: muscle memory of the removed menu — one release-note line, and the strip was
always the primary path.

## 1. One "Titles" tab, direction as state

- `Recent | Titles | Author | ★ | Search`. The star tab is a drawn glyph (~20 px,
  no text, no i18n); net strip width drops even though the slot count stays five.
- `SortOrder` is untouched (TitleAsc/TitleDesc remain two enum values — no format
  or persistence change). The tab maps to whichever of the two is current and
  remembers the last direction for the session.
- Direction is never hidden state: the active Titles tab carries a small drawn
  triangle (▴/▾ as a fillRect triangle, not a font glyph), and the header keeps
  announcing the full truth ("Library · Title Z-A").

Three affordances for flipping, novice → expert:
1. **A-Z grid mode line**: in title order the line reads `A→Z | Z→A` (the exact
   idiom "By first name | By last name" already uses in author order).
2. **Strip long-press** on the focused Titles tab: instant flip, triangle updates.
3. (The book-menu/details path never deals in direction — it is not a sort.)

## 2. Book menu (long-press on a row)

`OptionPopup` (existing component, existing release-swallow pattern) with:

- **Open**
- **Add to favorites / Remove from favorites** (label reflects current state)
- **Details**

Guards: unreachable while the grid is open or the strip is focused (their long-press
meanings differ); inert in the empty-list state.

## 3. Favorites

**The design decision that matters: favorites are primary data and must NOT live in
the CLX index.** The index is a derived cache — rebuilt, atomically replaced, and
"delete library.idx" is our documented corruption remedy. Favorites survive all of
that only in their own file.

- `/.crosspoint/favorites.dat`: `u8 version, u16 count`, then per entry
  `{u32 nameHash (fnv1a32 of the on-disk basename), u32 fileSize}` — the same
  identity the rebuild reconciliation uses, so favorites survive index rebuilds
  and folder moves. A rename loses the flag (same accepted trade as firstSeen;
  no size-only fallback here — exact match keeps it simple and safe).
- Bounds: accept ≤ 512 entries on read, log and truncate beyond. Load once in
  `onEnter` into a small sorted vector; membership test is a binary search.
- Writes are write-through on toggle (an explicit user action, not a hot path —
  the debounce rule targets per-page-turn writes, not this).
- **★ tab** = a filtered view reusing the exact `filtered` vector machinery search
  uses, composed with the current sort order. Zero new list plumbing.
- Row marker: a small drawn star/diamond in the left gutter of favorite rows
  (decide the exact mark in the simulator).
- Empty state teaches the gesture: "Long-press a book to add it to your favorites."
- Toast on toggle, matching the existing toast timing.

## 4. Details (from the book menu)

A simple full-screen page (ClearCache-style: render + Back), showing:
metadata title, author **with its provenance spelled out** (from folder name /
from the book's cache / from the EPUB package document), on-disk filename, folder
path, size, format. This is where the stored honesty finally reaches the reader.

## Implementation map

- `src/activities/library/LibraryListActivity.{h,cpp}` — gesture rewire, Titles
  tab, triangle, grid mode line for title order, ★ view, book menu, empty states.
- `lib/LibraryIndex/LibraryFavorites.{h,cpp}` (new) — format + parse host-testable
  pure; file I/O through HalStorage like LibraryIndexFile. Host test suite.
- Details page: small new activity or in-activity mode (prefer in-activity mode,
  like the grid — no lifecycle of its own).
- i18n (~9 keys, EN+FR): STR_LIBRARY_TAB_TITLES, four book-menu labels,
  STR_LIBRARY_FAVORITES_EMPTY, favorites toasts, three provenance labels.
- **No CLX format change, no version bump, no settings change.**

## Test plan

- Host: LibraryFavorites round-trip, bounds, corrupt-file rejection (same
  untrusted-input stance as the index).
- Simulator: full gesture-matrix walkthrough (each context × short/long × grid,
  strip, degraded, empty, ★-empty); FR label widths.
- Device: toggle → reboot → still favorite; rebuild index → still favorite;
  move file to another folder → still favorite; rename → documented loss.
