# Test releases and OTA updates

How a build gets from this repo onto a device over the air. The device asks
GitHub for the latest release of `oreglio/CrossInkLibrary` — a releases-only
repository (no source) whose one job is to hold firmware binaries.

## Version strings

- **Local dev build** (`pio run -e default`):
  `1.5.0-dev+<branch>.<hash>.<YYYYMMDD-HHMMSS>` — branch, commit and build
  instant to the second, so two images flashed back to back can always be told
  apart. Generated by `scripts/git_branch.py` into
  `lib/AppVersion/AppVersionGenerated.h` (untracked). The timestamp makes the
  nine files that read the version recompile on every build; accepted.
- **Release build** (`CROSSINK_RELEASE_VERSION=1.5.2 pio run -e default`):
  exactly `1.5.2`, nothing else. A release binary MUST announce the version of
  its tag — a dev binary published under a tag believes it is still 1.5.0 and
  will re-offer its own release forever.

## Cutting an OTA test release

```sh
CROSSINK_RELEASE_VERSION=1.5.2 pio run -e default
cp .pio/build/default/firmware.bin /tmp/firmware-x3-x4.bin
gh auth switch --user oreglio
gh release create v1.5.2 --repo oreglio/CrossInkLibrary \
  --title "v1.5.2 — <what changed>" --notes "<notes>" /tmp/firmware-x3-x4.bin
gh auth switch --user aurelien-edusign   # restore the usual account
```

The rules, each learned from the code rather than invented:

1. **The tag must be numerically greater** than what the device runs.
   `OtaUpdater::parseVersion` reads three numeric segments (optional leading
   `v`, everything after `-`/`+` ignored), so a device on `1.5.0-dev+...`
   updates to `v1.5.1` but never to a second `v1.5.1`. Bump the patch for
   every test release.
2. **The asset must be named `firmware-x3-x4.bin`.** The device looks for
   `firmware-<CROSSINK_FIRMWARE_DEVICE_TYPE>.bin`; the C3 envs define the type
   as `x3-x4`. The asset name is the uploaded file's basename — hence the `cp`
   to `/tmp` first. Variants like `firmware-x3-x4-<suffix>.bin` also match.
3. **A normal release, not a prerelease.** The device queries
   `releases/latest`, which excludes prereleases and drafts.
4. HTTPS is required for an unsigned image; GitHub's asset URLs qualify, so no
   sha256 manifest is needed.

On the device: `Settings > Check for updates` (Wi-Fi on).

## Traps

- **Hidden downgrade**: a device SD-flashed back to a dev build
  (`1.5.0-dev+...`) will be offered the latest release again, because the
  release is numerically newer than the dev base version. Ignore the prompt
  while testing dev builds, or cut a fresh release.
- **`gh` active account** flips between sessions. Release operations need
  `oreglio`; switch back after.

## SD fallback

Any build can always be flashed without OTA: copy the `.bin` anywhere on the
card and use `Settings > System > SD firmware update` (it is a file picker; no
fixed name required). Local test builds are kept in `firmware/` (gitignored)
as `CrossInkLibrary-<shortsha>.bin`, release copies as
`CrossInkLibrary-v<version>.bin`.
